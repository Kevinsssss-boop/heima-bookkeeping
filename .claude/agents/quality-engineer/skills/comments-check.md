# Comments Check（注释质量检查）

对项目代码进行全面的注释质量审查。详见全局命令 `comments-check.md`，以下是执行摘要。

---

## 3 大检查维度

### ① 注释覆盖率（够不够？）
目标比例约 **3 行注释 : 7 行代码（~30% 注释率）**

必须有的注释点：
- ✅ 文件顶部说明（用途、依赖）
- ✅ 每个函数/组件前的 JSDoc（功能、参数、返回值）
- ✅ 复杂逻辑处的内联注释（解释"为什么"）
- ✅ 关键变量用途说明
- ✅ 条件判断原因解释

评级：≥30% ✅优秀 | 20-29% ✅良好 | 10-19% ⚠️一般 | <10% ❌不足

### ② 内容匹配度（对不对？）
- 🔴 文不对题：注释说的 ≠ 代码做的
- 🔴 过时注释：代码改了但注释没更新
- 🔴 复制粘贴错误：复制了别的函数注释没改
- 🟡 注释过于笼统：只说"处理数据"没说怎么处理

### ③ 小白可读性（看得懂吗？）
- ✅ 用大白话、生活化比喻
- ✅ 解释"为什么这样做"，有什么坑
- ✅ 给出输入输出示例
- ❌ 避免专业术语、英文缩写、废话注释

**好注释示例：**
```javascript
// ✅ 好：大白话 + 使用场景
function add(a, b) {
  return a + b;
  // 两数相加：比如把"午餐20元"和"晚餐35元"加起来得到"今天餐饮总支出55元"
}
```

**差注释示例：**
```javascript
// ❌ 差：用了术语，小白看不懂
const result = arr.reduce((acc, cur) => acc + cur.value, 0); // 使用 reduce 进行归约操作
```

---

## 执行方式

逐文件分析：
1. 统计总行数、注释行数、代码行数 → 计算注释率
2. 逐条对比注释与对应代码功能是否一致
3. 评估每条注释是否能让零基础的人看懂

## 输出要求

输出格式化的注释质量报告，包含：
- 各文件注释率统计（表格形式）
- 匹配度评分（0-100）
- 可读性评分（0-100）
- 问题清单（精确到 文件:行号 + 修改前后对比示例）
- 改进建议（哪些地方需要补充/重写注释）

> 完整内容请参考全局技能文件 `~/.claude/commands/comments-check.md`
